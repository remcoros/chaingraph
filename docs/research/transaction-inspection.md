# Transaction and script inspection

Consulted 2026-09-08.

- [Bitcoin Core getrawtransaction](https://bitcoincore.org/en/doc/0.21.0/rpc/rawtransactions/getrawtransaction/) documents the distinction between verbose transaction observations and serialized hex, scriptSig, scriptPubKey, witness, txid and witness hash. The installed proxy already permits read-only non-verbose requests. No new backend indexing or persistence is introduced.
- [Esplora API](https://github.com/Blockstream/esplora/blob/master/API.md) describes inputs referencing previous outputs, explicit output spending information and raw transaction endpoints. This informed the creating/spending transaction chooser and the distinction between missing graph evidence and unspent status. Chaingraph uses its own Core/Electrum bridge, not a public Esplora service.
- [Esplora project](https://github.com/Blockstream/esplora) provides the familiar input/output inspection pattern. UI code here is original; no explorer implementation was copied.
- [bitcoinjs-lib](https://github.com/bitcoinjs/bitcoinjs-lib), installed version 7.0.2, supplies transaction deserialization, txid/wtxid calculation and normalized script ASM. Its MIT license is already included in the dependency notices. Raw decoding is inspection, not consensus, signature, or witness-commitment verification.
- [Bitcoin Core src/primitives/transaction.h](https://github.com/bitcoin/bitcoin/blob/master/src/primitives/transaction.h) (MIT) defines `COutPoint::IsNull` as `hash.IsNull() && n == NULL_INDEX` (UINT32_MAX) and `CTransaction::IsCoinBase` as a single input whose prevout is null. Raw-to-record binding therefore rejects only the exact null outpoint when the saved input claims an ordinary prevout; a zero hash at any other index is serialized like any other prevout and binds structurally without implying the output exists. No source was copied.
- The MIT-licensed `mempool-api-proxy` project files `src/domain/script-asm.ts` and `src/domain/transaction-formatter.ts` were reviewed after reading its LICENSE. They distinguish output scripts, input scriptSig and witness stacks and support Esplora-style opcode names. No source was copied. This implementation delegates normalized ASM to bitcoinjs and retains original hex; it deliberately reports malformed push data rather than presenting a best-effort decode as complete.

## Implementation boundaries

The browser computes related transactions solely from loaded transaction inputs and outputs. All loaded competing spending transactions remain available; a missing spend is not evidence of an unspent output. Lists initially show four rows plus any selected row, and can expand. The normal transaction view and advanced inspector are React components independent of the WebGL engine. Row selection and annotation actions call the same application handlers used by the graph.

Output script hex is available from saved transaction records. Raw transactions are fetched only on explicit request and held in component memory until the inspected selection or transaction changes, or its workspace closes. The byte limit is four million bytes, with a four-million weight-unit limit and the application's 10,000 input/output bound after parsing. Strict deserialization rejects trailing bytes. Returned txid and the loaded input outpoints, coinbase data, output values and available output scripts must agree before display. A txid authenticates non-witness serialization; it does not establish that supplied witness bytes match a block commitment. Script and witness data are never executed. Witness items are shown as bytes without guessing that every item is a script.

Synthetic laboratory transactions are observations with invented identifiers, not signed serialized transactions. Their raw transaction and witness data remain explicitly unavailable. Version-1 encrypted workspace shape is unchanged; raw inspection does not enlarge persisted records.

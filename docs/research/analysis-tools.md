# Analysis tools: evidence, scope and limitations

Research checked 2026-09-08. Implemented in `src/domain/analysis/`; all seven tools run locally over workspace records and make no network requests.

## Scope and result lifecycle

The application supplies the transaction IDs from the visible graph or the selected transaction. Omitted IDs in the domain API mean all loaded transactions; an empty list means none. Loaded previous transactions may supply input values and script evidence outside that scope. Reports distinguish the scoped transactions from supporting parents. This is a partial local view, never a claim about complete chain history.

Each run returns findings, coverage counts and an explanation when no matches exist. Results distinguish observations, ownership hypotheses and incomplete data. Parameter values are validated before execution. Findings support focus, graph isolation, exclusion and restoration. When input records or wallet coverage change, retained findings are marked for rerun. The panel also filters results by tool, evidence category and status.

## Implemented methods

| Tool                          | Method and useful follow-up                                                                                                                                                                                                              | Limits                                                                                                                                                                                                                                                                              |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Equal-output detection        | Group positive output amounts in integer satoshis. Minimum repeated outputs and input count are configurable. Highlight only members of each matching amount group; inspect other outputs separately.                                    | Excludes data outputs and coinbase. Repeated values do not identify CoinJoin and are not a linkability calculation.                                                                                                                                                                 |
| Common-input ownership        | Union co-spent input identities, following known locking scripts or addresses across scoped transactions. Missing parents remain outpoint references. Review supporting transactions and compare personal labels.                        | A hypothesis. By default, skip transactions with three or more equal outputs; the threshold and exclusion are configurable. Report skipped candidates, insufficient inputs, already-identical scripts and missing parents. This does not detect every collaborative transaction.    |
| Address reuse                 | Count output occurrences at decoded addresses within the chosen scope. Optionally require separate transactions. Inspect and label repeated outputs.                                                                                     | Same-transaction repeats are identified separately. Counts include spent outputs and are not balances. Unaddressed scripts are reported as unavailable for this comparison.                                                                                                         |
| Value flow and fees           | Sum all known previous output amounts and subtract all current outputs, using integer satoshi totals. Divide by a valid virtual size for sat/vB. Review all transactions or only missing data and fees meeting a configurable threshold. | Never substitute zero for a missing parent or raw byte size for virtual size. Coinbase is skipped. Invalid or negative totals are incomplete evidence. A threshold is the user's review criterion, not a market fee recommendation. Totals do not map individual inputs to outputs. |
| Consolidation and fan-out     | Configurable many-input/few-output counts and output/input ratio. Trace funding or distribution paths from matching transactions.                                                                                                        | Reports structure, not purpose. Data outputs are omitted from counts. Collaborative transactions and batching can share these shapes.                                                                                                                                               |
| Script-type comparisons       | Compare decoded known input/output script types, or outputs alone. Show mixed types and known type differences.                                                                                                                          | Missing types remain unavailable. The tool does not guess change, wallet software or owners.                                                                                                                                                                                        |
| Imported-wallet intersections | Match loaded inputs and outputs against addresses and script hashes already derived for imported wallets. Optionally restrict to co-spent inputs. Inspect possible connections between wallet records.                                   | Overlapping import coverage is explicitly distinguished from separate participants. Missing derivations and parents limit coverage. Matches do not identify real owners or allocate specific inputs to outputs.                                                                     |

## Primary references and attribution

- [Meiklejohn et al., A Fistful of Bitcoins (IMC 2013), author-hosted paper](https://cseweb.ucsd.edu/~smeiklejohn/files/imc13.pdf): foundational input and change clustering research. Its empirical setting is historical; no reported accuracy is transferred to this application.
- [BIP78, PayJoin](https://github.com/bitcoin/bips/blob/master/bip-0078.mediawiki): collaborative input ownership and the limitations of common-input and script-based change assumptions. This motivates explicit hypotheses and the absence of automatic change attribution.
- [Samourai Wallet Boltzmann](https://github.com/Samourai-Wallet/boltzmann): transaction entropy and input/output linkability are a distinct combinatorial analysis. Our equal-output grouping does not implement that algorithm or provide a probability/privacy score. No upstream implementation code was copied.
- [Bitcoin developer guide, transactions](https://developer.bitcoin.org/devguide/transactions.html): outpoint references, output amounts, scripts and fee accounting. Shape thresholds in this application are user controls, not protocol-defined transaction classes.
- [BIP141, Segregated Witness](https://github.com/bitcoin/bips/blob/master/bip-0141.mediawiki): virtual transaction size and witness-aware accounting. Fee rates require the transaction's virtual size.
- [BIP32, Hierarchical Deterministic Wallets](https://github.com/bitcoin/bips/blob/master/bip-0032.mediawiki): public derivation and partial wallet sharing. Imported coverage is bounded by the addresses already derived; two imports need not represent two independent wallets.

## Validation

`tests/analysis.test.ts` exercises exact equal-output membership, CIOH exclusions and raw-script continuity, scoped reuse, complete and incomplete fee arithmetic, virtual-size requirements, configurable shapes, partial script comparisons, imported wallet overlap, script-only membership, option validation, non-mutation and persisted schema compatibility. Existing workspace regression tests additionally cover the 150-input/output fixture and removable grouping overlays.

No Boltzmann solver, dust-policy classification or real-world ownership attribution is implemented by these tools. Future linkability work needs explicit computational bounds and reference vectors before exposing probabilities.

Manual fresh-context browser review on the running development application passed all seven tool runs and coverage reports, tool search, result search and type/status filters, exclusion/restoration, selected-transaction scope, changed threshold with a no-match result, rerun, and graph isolation. The 375px mobile view had no horizontal overflow; no uncaught browser errors occurred. Sticky Tools/Findings navigation and automatic result scrolling were reviewed visually. This flow used the synthetic laboratory, with no upstream transaction requests.

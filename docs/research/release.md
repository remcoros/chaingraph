# Container and release research

Reviewed 2026-09-08. These primary sources informed the deployment and release machinery; no upstream application source was copied.

| Source                                                                                                                                                                                                         | Applied decision                                                                                                                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| [Docker multi-stage builds](https://docs.docker.com/build/building/multi-stage/)                                                                                                                               | Compile frontend and bundle the server in a build stage; copy runtime artifacts only.                                                           |
| [Docker Compose environment files](https://docs.docker.com/compose/how-tos/environment-variables/set-environment-variables/) and [service reference](https://docs.docker.com/reference/compose-file/services/) | Explicit runtime env file, raw values, read-only root, dropped capabilities and no-new-privileges. Raw env files require Compose 2.30 or later. |
| [Docker build attestations in Actions](https://docs.docker.com/build/ci/github-actions/attestations/) and [attestation storage](https://docs.docker.com/build/metadata/attestations/)                          | Publish provenance and SBOM with the registry image. | [GitHub container publication](https://docs.github.com/en/actions/tutorials/publish-packages/publish-docker-images?learn=continuous_deployment)                                                                | GHCR publication uses the repository-scoped GITHUB_TOKEN, after release validation and tests.                                                   |
| [GitHub Actions secure use](https://docs.github.com/en/actions/reference/security/secure-use)                                                                                                                  | Pin actions to verified commit SHAs; grant packages write only to the publication job.                                                          |
| [Official Node image Dockerfile](https://github.com/nodejs/docker-node/blob/main/24/bookworm-slim/Dockerfile)                                                                                                  | Node 24 Debian slim runtime with its nonroot node user and system CA package.                                                                   |

The actual registry index for `node:24.20.0-bookworm-slim` was verified with `docker buildx imagetools inspect`; Dockerfile pins `sha256:ba849c60be29959425b8734d57b8b4b7d56f98edd9504c9af091d5281095a71e`. Action commit pins were resolved from their upstream major-version tags with `git ls-remote`. Pins are verified inputs, not a promise of bit-for-bit reproducibility: Debian package repositories and the mutable Dockerfile frontend still receive updates. Recheck the Node tag and index together during maintenance.

## Local validation

Docker 29.8.0 / Buildx 0.37.0 built and loaded the linux/amd64 production image. A running container served HTML and bundled JavaScript, negotiated Bitcoin HTTP RPC and Electrum TCP against local protocol fixtures, returned chain status/history, rejected an unlisted spending RPC and an untrusted Origin, and exited cleanly on SIGTERM. Runtime assertions confirmed UID 1000, an unwritable application filesystem, the system CA bundle, absence of environment files and node_modules, and a successful image health-check command. These fixtures prove the bundled transport paths execute; they do not claim validation against live upstream servers.

Compose 5.5.1 also started the image with an explicitly selected example env file, reached healthy status, served the UI and shut down cleanly. Container inspection confirmed the Compose read-only root, node user, dropped capabilities and no-new-privileges settings.

Tag metadata validation accepts v0.2.0 and rejects a mismatched tag. GitHub publication and native ARM execution remain unverified locally; no tag or image was pushed. The release workflow runs browser checks against its built production container before publication.
